## 跑 n8n 需要什么配置的服务器

内存是第一指标，CPU 可以放宽。n8n 官方文档在部署前提里写得很明确：n8n 不太吃 CPU，规划服务器时应该把资源集中在内存上。参考数字是空闲时约 100 MB、实际运行 320 MB 到 2 GB；数据库默认用 SQLite，不单独配置也能跑，需要更高并发时换 PostgreSQL。

选服务器之前还要知道一个变化：n8n 3.0（2026 年 10 月发布）已经不再支持 npm 安装，`npx n8n` 这条路走不通了，自托管只能跑 Docker。官方给了一行命令安装：`curl -fsSL https://get.n8n.io | sh`。这对选机的影响是——你不用纠结 Node.js 版本，但机器必须能顺畅跑 Docker。这也是 512 MB 内存的机器不适合拿来跑 n8n 的原因：Docker 本身加上系统开销，1 GB 以下内存会非常紧。

官方文档里还有一条容易被忽略的提醒：Code 节点在处理数据时会做前后处理副本，遇到大体积二进制文件可能耗尽全部可用资源。工作流要处理大文件的话，内存往上加一档。

## 买之前要知道的几个限制

**这是无托管服务（unmanaged）**。系统装不上、端口不通这类问题要自己解决，RackNerd 的 24/7 支持管的是硬件、网络和面板层面的故障。完全没碰过 Linux 命令行的话，这个学习成本要提前算进去——好在 n8n 官方的一行安装脚本已经把部署难度压得很低。

**Docker 明确允许，但别想在 VPS 里再套虚拟机**。RackNerd 的服务条款写得很清楚：Docker、Docker Compose、Kubernetes 这类容器化负载在 KVM VPS 上是允许的——这正好覆盖 n8n 的部署需求；但嵌套虚拟化（在 VPS 里再跑虚拟机或需要硬件虚拟化的模拟器）未经书面批准不允许，条款也不保证 VPS 暴露 VT-x/AMD-V 标志。想在虚拟机里折腾系统的，该看的是独立服务器产品线。VPS 还适用 fair-share 原则，长期跑满 Disk I/O 或 CPU 会受到限制。

**容器必须挂载持久卷，宕机期间的工作流不会补跑**。n8n 官方文档的表述很直接：容器化环境如果不持久化挂载卷，停止或重启后所有数据丢失；实例宕机或重启期间错过的 Cron 和 Webhook 触发无法恢复。官方的建议是夜间备份时挂载另一个容器复制全部数据，RAM 占用可以忽略。自己定期备份数据卷，是自托管方案里你代替云托管商承担的那部分责任。

**线路没有 CN2**。有第三方测评提到 RackNerd 走普通国际线路，国内用户选机房时一般建议洛杉矶 DC-02 或 DC-03，延迟相对友好。跑 n8n 这种后台自动化影响有限——工作流在服务器之间执行，你只在配置和查看结果时登录后台。可用性方面，其 SLA 承诺 99.999% 的网络和电力不间断，超出部分按每小时月费 2% 抵扣、上限 50%，抵扣需在故障后 30 天内申请。

## 常见问题

**1 GB 内存的机器真能跑 n8n 吗？**
能，但只推荐试水。官方参考的内存下限远低于 1 GB，轻量工作流没问题；Docker 和系统本身会占掉一部分，留给 n8n 的空间有限，跑复杂工作流或处理大文件容易吃紧。

**数据库用 SQLite 还是 PostgreSQL？**
起步用默认的 SQLite 完全可以，n8n 会在没有配置数据库时自动创建。并发上来后迁到 PostgreSQL，官方建议每个 n8n 实例配一个专用数据库，避免性能互相拖累。

**服务器重启后 n8n 的数据会丢吗？**
正确挂载了数据卷就不会丢。丢数据几乎都是启动命令里忘了挂载卷——这是 n8n 官方文档专门强调的一条，装完检查一遍。

**特价套餐第二年续费会涨价吗？**
不会，官网 FAQ 明确特价套餐终身同价续费。

**在 VPS 里跑 Docker 合规吗？**
合规。RackNerd 服务条款明确允许 Docker、Docker Compose、Kubernetes 等容器化负载，被禁止的是未经批准的嵌套虚拟化（在 VPS 里再跑虚拟机）。n8n 的部署方式正好落在允许范围内。

**能装 Windows 吗？**
RackNerd 的月付产品线里有 Windows VPS，但跑 n8n 用 Linux 系统就行，没有理由为此多花钱。
